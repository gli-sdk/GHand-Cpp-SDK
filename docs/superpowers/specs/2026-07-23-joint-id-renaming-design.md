# C++ SDK 关节枚举命名同步设计

## 目标与范围

将 GHand C++ SDK 的 `JointId` 关节名称同步为 Python SDK 当前使用的名称，同时保持枚举底层数值、协议寄存器地址、角度限制和控制行为不变。

本变更只修改 `E:\GHand-Cpp-SDK`。Python SDK 仅作为命名依据，不在本变更中修改。

## 名称映射

| 当前 C++ 名称 | 新名称 | 底层数值 |
|---|---|---:|
| `THUMB_DIP` | `THUMB_IP` | 0 |
| `THUMB_PIP` | `THUMB_MCP` | 1 |
| `THUMB_MCP` | `THUMB_TMC_FE` | 2 |
| `THUMB_SWING` | `THUMB_TMC_AA` | 3 |
| `THUMB_ROTATION` | `THUMB_TMC_PS` | 4 |
| `FF_SWING` | `FF_MCP_AA` | 8 |

其他 `JointId` 名称和数值保持不变。

## 公共 API 与兼容性

`JointId` 位于已安装的公共头文件 `include/ghand/types.h`，因此本变更会造成源码不兼容。使用旧枚举名称的下游代码必须迁移到新名称。

不提供旧名称兼容别名。旧 `THUMB_MCP` 表示数值 2，而新 `THUMB_MCP` 表示数值 1，两者存在名称和语义冲突，无法同时提供安全的同名兼容接口。

枚举底层类型仍为 `uint8_t`，枚举顺序和数值保持不变。因此：

- 不改变协议中的关节编号。
- 不改变公共结构体布局或类型大小。
- 不新增或删除导出函数。
- 不改变 C++ 标准、编译器或标准库要求。
- 已编译消费者若只在二进制边界传递枚举数值，其数值语义不变；重新编译使用旧名称的源码会失败，需要迁移。

## 变更位置与职责

实施阶段采用一次性原子重命名：

- `include/ghand/types.h`：更新公共 `JointId` 枚举名称。
- `src/types.cc`：更新 `ToString(JointId)` 的分支和输出文本。
- `src/internal/product_config_loader.cc`：更新配置名称解析和产品默认协议映射。
- `config/*.json`：将关节配置键更新为新名称。
- `src/` 下其他引用：更新内部控制、通信和映射代码中的枚举名称。
- `examples/`：更新所有教程和演示代码。
- `tests/`：更新现有断言，并补充枚举值、字符串转换及配置解析验证。
- `README.zh.md` 和其他实际引用关节名称的文档：同步新名称。
- `CHANGELOG.md`：仅当仓库存在并采用该变更记录文件时，记录破坏性重命名和迁移映射。

不重构与命名同步无关的代码，不修改寄存器地址、角度范围、产品配置语义或通信流程。

## 数据流与行为

用户代码通过 `JointId` 构造 `JointCommand`。内部控制和通信层继续按枚举底层数值查找产品配置及协议地址。此次变更只替换名称，不改变该数据流。

JSON 产品配置中的关节名称由 `JointIdFromString()` 解析。配置文件和解析器将同步切换到新名称。旧配置名称不再接受；遇到旧名时维持当前未知名称处理方式。

`ToString(JointId)` 返回对应的新名称，日志和示例输出因此与 Python SDK 保持一致。

## 错误处理

不新增错误类型或异常。未知配置名称仍记录警告并返回 `JointId::NUM_JOINTS`。无效枚举值的字符串转换继续沿用现有行为。

## 验证方案

实施遵循测试先行：

1. 添加或调整测试，断言六个新名称对应数值 `0`、`1`、`2`、`3`、`4`、`8`。
2. 断言 `ToString()` 返回新名称。
3. 验证 G5 和 L1 配置使用新名称加载成功，关节数量、角度限制和协议地址保持不变。
4. 验证 CAN FD、EtherCAT、RS485/Modbus 相关纯软件协议测试不因重命名回归。
5. 全仓搜索确认生产代码、配置、测试、示例和文档中不再残留六个旧名称。
6. 运行 CMake 配置、完整构建和软件测试。

需要真实设备的测试单独报告；未执行硬件验证时，不将软件测试结果描述为硬件验证通过。

## 成功标准

- C++ SDK 对外只暴露 Python SDK 当前使用的六个新名称。
- 六个枚举底层数值和所有其他枚举值保持不变。
- 配置、内部实现、日志、示例、测试和文档使用一致的新名称。
- 相关构建和纯软件测试通过。
- 交付说明明确标注源码破坏性变更及旧名到新名的迁移映射。
